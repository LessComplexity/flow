## What works

**P5/M2 complete (S13).** Text emitter `emit(&CategoryIr) -> Result<String, EmitError>` (`src/lib.rs`) realizing `F_LLVM` as a `.ll` String, plus the shared `crates/flow-rt` runtime (7 print externs + `flow_trap` exit-101) it links against.

- **Parallel orchestrator v1 (S24; `plans/plan-parallel-orchestrator.md`, ratified)** — a multi-task `flow_main` emits the parallel form: one `%Frame` struct holds every object slot (task fns GEP off `ptr %frame`; update-elision aliases share fields); one `define internal void @task{i}(i64 %lo, i64 %hi, ptr %frame)` per `path_plan` task (Split = the bulk element loop over `%lo..%hi` via `bulk_bounds`; Seq = the chain/fold/pure-loop morphisms verbatim); the host spine registers the static table (`flow_par_begin/task/pin/dep/launch` with compile-time ranks and deps), interleaves token ops with checkpoint `flow_par_wait`+`flow_par_check` pairs (packed `(task<<32)|threshold` constant arrays; threshold = watermark, `u32::MAX` = completion), executes pinned tasks inline via `flow_par_run_pinned` after a dep-wait+check, and closes with `flow_par_finish`. **Speculate-and-order guards** (plan §2 rule 3): task/body-fn trap arms call `flow_par_trap(site_topo, kind)` and continue with a zero dummy — branch-around keeps `sdiv`/`srem`/loads off the bad path (no UB), Update skips only the element store; scalar chain tasks publish `flow_par_watermark` after each guarded site; `bounds_proof`-proven elisions and the constant-divisor credit are unchanged. Body fns of parallel sites emit the task flavor via the site-topo map (`lib.rs:parallel_body_sites`) and drop `readonly` (`FnEmit::runtime_write`). Single-path fns and every non-entry fn emit today's sequential text byte-identical (v1 scope: `flow_main` only — recorded ceiling). flow-rt: global work-stealing pool (rank-seeded per-worker deques, help-first waits, `FLOW_PAR` env, `GRAIN=4096` slices, CAS-min trap flag, per-task watermarks, registration-time pinning). R-PAR is pinned live: trap-mid-parallel stdout-prefix parity, `FLOW_PAR=1`/`8`/unset byte-equality, run-twice equality, big-N split parity — all at `-O0`+`-O2`.

- **Heap lowering (S29; `plans/plan-s29-openblas-levers.md` item 4, DESIGN §2 + BL9)** — `func.rs:HEAP_MIN_BYTES` (256 KB) gates `func.rs:FnEmit::entry_alloc`, the ONE seam every sizeable entry-block block goes through (`allocate_local_slots`, `packed_buffer`, `allocate_frame_packs`, and the `%Frame` block in `emit_parallel`; the fixed small scratches — `scratch`, the KC a-panel pack — stay direct `alloca`s, all far below the threshold): at or above it the block becomes `call ptr @flow_rt_alloc(i64 bytes, i64 align)`, below it today's `alloca`, byte-for-byte. An `alloca` result and an arena block are both a `ptr`, so no `getelementptr` consumer changed. Sizing is `func.rs:llt_bytes` — the emitter's own LLVM `StructLayout` walk over the closed type grammar `ty.rs` emits, checked against `ptrtoint (ptr getelementptr (%Frame, ptr null, i32 1) to i64)`; unrecognised text sizes to 0 and stays on the stack (the conservative direction). One `flow_rt_free_all()` before the entry fn's `ret` is the whole teardown — past `flow_par_finish` and past the return value's load, so plan-s29 composition rule 4 holds in both flavors from a single emission point, and since only the entry fn registers blocks, "free everything" is exactly "free mine". `module.rs:HEAP_DECLS` is gated on the **emitted text** containing `@flow_rt_alloc`, not on a re-derived predicate — a program that heap-allocates nothing is byte-identical to before, declaration block included. flow-rt gained the arena (`flow_rt_alloc`/`flow_rt_free_all` over a `Mutex<Vec<(usize, Layout)>>` registry; blocks uninitialised, like the `alloca` they replace; allocation failure aborts — the emitted program has no OOM path). **Effect (S29 local run):** `benches/matmul/matmul2048_cap_f32.flow` runs locally for the first time (prints `-1045` / `51275`) — it used to SIGSEGV on the 64 MB macOS stack. Note the checked-in `benches/matmul/*.ll` artifacts predate the change (the bench runner regenerates them); a 2048/4096 entry frame now emits the arena call where the committed text still shows `alloca %Frame`. **Recorded ceiling (BL9):** entry function only — a big array local to a Named fn or a Map/Fold body keeps its `alloca`, because those run an unbounded number of times and arena placement without a per-call free point (which the emitter does not compute) would grow without bound.
- **`time` builtin — the llvm half (S29; `../lower/plans/plan-time-builtin.md`)** — `func.rs:FnEmit::emit_time_ms` emits `call double @flow_time_ms()` + store at the morphism's topo position; `module.rs:RT_DECLS` declares the extern unconditionally (NOT gated on `perf_timing` like `PERF_DECLS`). The source `IoToken` erases and the `(IoToken, f64)` target's residual has arity 1, so it materializes as the bare `double` — the call result IS the target's value and no pair is built. flow-rt's `flow_time_ms` reads the same monotonic clock as `flow_perf_begin`/`flow_perf_end`, against one process-lifetime `Instant` epoch, so two reads are non-decreasing and their difference is real elapsed ms. `FnAttrs` needed no new arm: a `TimeMs`-bearing fn owns token-typed objects, which the existing token rule already keeps attribute-free. The two ordering fixes that make a bracket mean anything under the parallel orchestrator are flow-ir's (`path_plan`: the source-order fence, and the host cone that keeps a clock value's consumers on the spine); this backend's emitted text is where they are pinned — `golden_ll.rs:time_bracket_fences_the_tasks_it_brackets` asserts `t0`'s wait set is non-empty and `t1`'s strictly larger, and that the `fsub` follows both reads.

- **Op table (§2)** — every Core op emits (`func.rs`): wrapping int `add/sub/mul` (no `nsw`/`nuw`); signed `Div`/`Mod` with zero-guard + `MIN/-1` guard (Div ⇒ `MIN`, Mod ⇒ `0`, `wrapping_div`/`wrapping_rem` parity); u8 `udiv`/`urem`; IEEE floats at width (`fadd`..`frem`, `fneg`); int/float compares (`fcmp` ordered, `une` for `!=`); `select`-Phi (strict, both cones execute — BL2); `Pair`/`Proj` as GEP store/load; `Call` direct; counted-loop `Map`/`Fold`/`Zip`/`Enumerate`; `Print` via flow-rt at its topo position.
- **Loop CFG (§3)** on `flow_ir::loop_plan` (BL7 — the one-source-of-truth per-merge attribution predicate; `loops.rs:emit_loop`): guard-first quartet (`entry`/`header`/`advance`/`exit`/`after`), decide cone every iteration incl. the exit one, advance cone unreachable on exit. Two sequential loops per fn work; an exit-only computed payload is emitted exactly once (driver-owned, `walk()`).
- **Token erasure (L4)** — arity-0 (no slot), arity-1 (bare component, plain store/load), arity-≥2 (`{…}` struct + GEP), remap derived on demand from the ty (`ty.rs`).
- **`Update` (ADR-0021)** — same index guard as `Index`; the whole-array `llvm.memcpy` into a fresh target slot fires only when flow-ir's `last_use_plan` cannot prove the source dead (suggestion #2, applied 2026-07-22 — the plan-last-use §2 rule 4 consumer): when the source array is `dead_after` the update (uses ranked decide < `LoopExit` < advance < `LoopBack`, ¬escapes, ¬carried — the loop-carried matmul4 shape), the memcpy is skipped and the target shares the source's slot, the element store landing in place in the merge's own storage (`func.rs:emit_update`; legality `func.rs:FnEmit::update_in_place_source`; pre-pass `FnEmit::{lup, elided_updates}` so an elided target mints no alloca). Ptr-resident (by-ref/borrowed) sources are vetoed explicitly — never written in place.
- **By-reference array captures (ADR-0027; suggestion #6, applied 2026-07-21)** — a Map/Fold body fn's first-k Array input components lower to `ptr` (`ty.rs:lower_body_input_ty`; k from the unique Map/Fold site, `func.rs:FnEmit::body_captures`). A captured-array Proj lands in an `alloca ptr` holding the forwarded pointer (`FnEmit::ptr_resident`); `Index`/`Update`/`Map`/`Fold` array operands read through it (`func.rs:array_operand_ptr`); the body call's scratch carries addresses, not array bytes (`func.rs:body_call_arg` — the transitive fold-in-map case forwards the loaded pointer). Escaping uses (`Pair` into ordinary products, `Call`, `Output`) deep-copy through the pointer in `load_whole` — observably identical to the inline value (read-only capture semantics; the interp oracle is representation-blind). k=0 bodies and scalar captures emit byte-identical text to before.
- **By-reference array call args (BL5 amendment; suggestion #8, applied 2026-07-21)** — a Named fn's top-level Array input (the input itself, or direct product components) lowers to `ptr` (`ty.rs:lower_named_input_ty` — the capture lowering with `k = u32::MAX`; nested products-in-products stay by value, a recorded limitation). The callee's array parameters ride the same ptr-resident machinery as captures (`FnEmit::byref` with `k = u32::MAX`; a bare-Array input is itself ptr-resident, its slot an `alloca ptr`); `func.rs:emit_call` assembles the argument through the `body_call_arg` template — array components store their address (forwarding ptr-resident feeders), scalars their value — so all call sites (host paths and body fns) agree with the callee per-signature by construction. `array_operand_ptr` also covers an op reading an array component straight off the by-ref input product (a `load ptr` from the field), and `Zip`/`Enumerate` route through it; `load_whole` assembles the by-value whole of the by-ref input product for escaping uses. Scalar-only arguments emit byte-identical text to before.
- **Truthful fn attributes (suggestion #7, applied 2026-07-21; proof-refined 2026-07-22, wave 4)** — `func.rs:FnAttrs` computes the conservative syntactic capability set per fn (no integer `Div`/`Mod`, no trap-capable `Index`/`Update`, no `Print`/token use, and transitively-clean callees over `Call` + `Map`/`Fold` body edges — the `TrapCaps` fixpoint spirit). Clean fns emit `readonly nounwind`, plus `willreturn` when the closure has no `LoopEnter` and no call/body cycle (a `willreturn` violation is UB — a possibly-diverging loop must never carry it); a clean fn's bare-`ptr` by-ref parameter additionally gets `noalias nocapture readonly` (never written through, never escapes, the single pointer argument). Unclean fns stay bare, so trap behavior and print ordering are untouched by construction. `flow_trap` is declared `noreturn` (flow-rt defines it `-> !`); print externs stay attribute-free. **Wave-4 refinement:** a `bounds_proof`-PROVEN `Index` is not trap-capable (its guard is elided — no trap path exists), so it no longer counts against the clean set (`func.rs:FnAttrs::analyze` computes the per-fn proof plan); `Update` stays counted (conservative this wave).
- **Proven-`Index` guard elision (S20 `bounds_proof` consumer, applied 2026-07-22, wave 4)** — `func.rs:FnEmit::bp` holds the fn's `bounds_proof` plan (computed once in `FnEmit::new`, next to `lup`); `emit_index(m, …)` drops the two-sided guard (`icmp slt`/`icmp sge`/`or` + the `flow_trap(1)` block) when `bp.proven(m)` — the plan shows the index statically inside `[0, n)`, so the trap is dead and trap-freedom is exact — emitting just the type-directed extension + GEP + load. Everything unproven (unknown/wrapping/loop-carried indices — fir's `coeffs[k]`, the one-kernel matmul's fold body, suggestion #9) emits today's guard byte-identical; `Update` keeps its guard regardless. The trap kind+1 encoding, exit-101 protocol, and `guard_index` itself are unchanged — only dead guards disappear.
- **`Iota`/`Fill` (ADR-0029, stage 1, applied 2026-07-22)** — the array-construction primitives emit as `i64`-indexed store loops (`func.rs:emit_iota`: `out[i] = trunc i64 iv to i32`, count read from the target type — validate ties it to the `Constant` source; `func.rs:emit_fill`: `out[i] = x` from the internal pair's slot 0). Trap-free by construction (no guard, no trap param). Compile-and-run oracle parity pinned by `tests/differential.rs::differential_iota_fill`.
- **`zeroext` ABI** — every `i8`/`i1` param carries `zeroext` in the `declare` lines and at every call site; the attr goes **after** the type in call args (`i8 zeroext %v`) — the S13 fix for the invalid-LLVM attr-before-type form that clang's own bug-hunt caught.
- **Determinism (L2)** — names from per-fn ordinals + a rising counter, never slotmap bits; emit twice is byte-equal.
- **Differential harness** — emit → `clang <prog>.ll libflow_rt.a -o prog` → run (time-boxed) → compare per L1, **at both `-O0` and `-O2`** for every case (the DESIGN §8 `-O2` row, added in the post-review pass; optimization is where accidentally-relied-on LLVM-level UB would surface); examples raw + rewritten, closed-mode testgen sweep (≥256 cases × raw+rewritten, fanned across `available_parallelism` threads), u8 ABI, matmul loop-driven Update, traps exit-101. Render parity to interp is pinned in flow-rt's unit table.

## What does not / known issues

- **Nested loops (multi-merge SCC) ⇒ `EmitError::Unsupported { "nested loops" }`** (L3/BL6; `lib.rs:emit` gate) — the same scope boundary as interp M1 and rewrite RW8; lifted across the toolchain in one increment or not at all.
- **Alloca-slot stack ceiling (BL1) — the ENTRY face closed S29, the callee face open (BL9).** Entry-block blocks of ≥ 256 KB in the entry function are arena blocks now, so the 64 MB macOS wall no longer caps whole-program array size (2048² f32 runs). What remains: a big array local to a called `Named` fn or a Map/Fold body still lives in that fn's frame — those run an unbounded number of times, so arena placement needs `flow_rt_free(ptr)` + `LastUsePlan`-driven free points the emitter does not compute yet (plan-s29 Ceilings). Consequence: a `matmul2048` written with its kernel in a named fn still hits the stack wall; the all-in-`main` capture form does not. The sepia perf shape is unrevisited: `perf_baseline.rs:run_big_stack` still raises the limit via `ulimit -s hard` (whether its per-object slots cross the 256 KB threshold at a given N was not measured this session). **BL1's other two faces died in S21:** the literal-store module blowup (ADR-0029 procedural sources — 23 MB `.ll` → 21 KB) and the first-class-aggregate optimizer blowup (WP3b — staging copies were `load [65536 x double]` SSA values; clang -O2 on matmul256_cap went from OOM-kill/222 s+ to 0.08 s / 57 MB; `capture_array_staging_never_loads_whole` pins the shape).
- **Perf N capped at 4096** — the array literal is N `Pair` stores (Core has no array-fill); at N = 262144 clang `-O2` needs >25 min CPU on the ~1M-line module and 65536 is still minutes (observed S13). 4096 already shows the scale story unambiguously; an array-fill primitive / heap lowering restores large N.
- **Diverged testgen programs are skipped** in the differential (no finite native observable); open-mode `i32 → i32` testgen is excluded (no native `@main` analog, BL8).
- ~~**conv2d_512 leg-level vs kernel-level — the gen measurement boundary (S28)**~~ — **CLOSED S29 by the `time` builtin** (suggestions #14): `benches/shapes/*.flow` open their own bracket after generation and print `iter ms=`, so the flow leg now spans what the baselines span. The S28 estimate it invalidates: the conv2d 512 kernel is **0.083 (conf) / 0.107 (fma)**, ahead of cpp-mt 0.112 by 1.3× — not the "≈0.04, 3× over cpp-mt" S28 recorded, which was a subtraction rather than a measurement. `benches/matmul/` is NOT migrated (still FLOW_PERF, so its totals still include generation — fine for A/B against S28 on the same basis, wrong for cross-language verdicts).
- **conv2d does not scale — the TI=1 row-blocking ceiling, now MEASURED (S29)** — kernel-only, conv2d beats cpp-mt at side 512 (0.083 vs 0.112) and **loses 3.4× at side 1024** (0.445 vs 0.133): cpp gains superlinearly across the size step while Flow degrades, because `emit_tiled_map_conv` re-loads every img window row per output row (`b.ci == cq` — reuse ×3 left on the table) and that term takes over once the working set stops fitting. Suggestions #11 (TI over output rows) / #12 (im2col, which reaches the whole matmul ladder instead of one rung) are no longer speculative — this is their measured motivation (#17).
- **The KC rung is off by default and unmeasured where it was designed for (S29)** — bit-exact and fully tested, but a 3× loss on M4 Pro at 1024 f32; the box leg (zen3 at 4096, where the 16 GB of A re-reads that motivated it live) has not been run. Either that measurement or the parking-free order recorded in plan-s29 Ceilings decides it (suggestions #16).

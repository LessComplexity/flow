## Categorical model (Dat + Trn)

**Firewall.** Level B: these are the compiler's own types. The emitted `.cu` text *represents* the image of `F_CUDA : Flow-Cat → CUDA-Cat` (Level A, category-ir §8.2); this section models the emitter and the runtime boundary its image crosses.

**Physical pair — real for the first time.** backend-llvm's DESIGN recorded its physical pair as degenerate: emission is one in-process pass, and the only genuine `Loc`s were the harness's `clang` subprocess and the native process. Here the pair is the design itself. There are two sites — the **host process** and the **GPU device** — and the transmissions between them (`cudaMemcpy` H→D / D→H) are the first `Trm`s in the project whose cost is real, priced, and latency-visible. This is the ADR-0022 D2 test case: the section below must *earn* its keep by producing something the code alone would hide. The keep-test this DESIGN proposes, to be judged by the adversarial review: the model must yield (a) a **complete** transfer inventory (§2 — every H↔D crossing enumerated; the review failing to find a missing crossing is the pass condition) and (b) the trap-flag visibility rule (§3) as a consequence of the two-site structure, not an afterthought. **Outcome (2026-07-18 review):** (a) **failed on first use** — the review found three missing crossings (CC-1a/b/c; §2 below is the completed inventory); (b) holds in reframed form (CC-4, §3). The model earned its keep by failing: the first finding the Level-B apparatus has produced — `reviews/review-design-p6.md`.

### Why (one paragraph)

Three payoffs. (1) **§8.5 piecewise correctness is the code shape**: `emit` walks `topo_order` translating one morphism at a time — scalar morphisms become host C++ statements, array-bulk morphisms become kernel launches — and global correctness is the same differential law as llvm's, `run_cuda ∘ emit ≈ run`, discharged on examples + testgen programs, not argued. (2) **§8.2's functor story gets its empirical test**: the spec says map-fusion in the source is preserved by `F_CUDA` and becomes kernel fusion "without a separate pass"; the rewrite layer's `fuse` channel already synthesizes fused `Map` bodies (`flow-rewrite/src/replay.rs:78–84`, `synthesize_fused`), so one fused `Map` in rewritten IR becomes exactly one launch here — the §8.2 prediction is checkable by counting launches on rewritten IR, and where the rewrite does *not* fuse, fusion is recorded headroom, not claimed (§7). (3) **The one-runtime seam (ADR-0020 §2) deletes the same two differential-killers** — float text and trap UB — with the CUDA-specific strengthening that *all* effects stay host-side: every print and trap calls `flow-rt` on the host, and E2's "no effects in parallel fanout" is realized as "no effects in kernels" (host-only prints were the S13 design seed, next-session.md).

### Transforms (Trn) and transmissions (Trm)

Compile-time `Trn`s (the emitter): `emit : &CategoryIr → CuText ⊕ EmitError` (ADR-0020 signature, deterministic L2) · `emit_fn` (one host C++ fn per `FuncDef`; `__device__` twins per §1 Call) · `emit_morphism` (per `topo_order` step — host statement *or* launch, §1) · `emit_kernel` (one `__global__` per array-bulk op site) · `emit_loop` (host-driven quartet per `flow_ir::loop_plan`).

Runtime `Trn`s (the functor's morphism images): host-statement evaluation (scalar ops, prints via `flow-rt`) and **kernel launches** (array-bulk ops; one-thread-per-element elementwise kernels, the full-copy `Update` kernel, the single-thread `Fold` kernel).

| `Trm` | Direction | Payload | When |
|---|---|---|---|
| `up` | H→D | literal array data (`cudaMemcpy`, once per construction execution) | §2 inventory item 1 |
| (launch args) | H→D | scalar kernel arguments — ride the launch, **not** a memcpy; counted separately | §2 item 2 |
| `zero` | H→D | the trap-flag initial zeroing (`cudaMemset`, 4 B) | §2 item 3 — **once per process** |
| `down` | D→H | `Index` scalar results; `Fold` scalar accumulators; the trap-flag read after **every** launch | §2 items 4–6 |
| `err` | D→H | `cudaError_t` — every `cudaMalloc`/`cudaMemcpy` return + `cudaGetLastError()` after every launch; host-consumed, drives the infra-failure exit (§3) | §2 item 7 — per API call + per launch |

Whole-array D→H: **zero, by construction** (§2 — L5's theorem). That there is no host consumer of array data in Core (arrays are unprintable, L1207; every array op has a device realization; the wrapper prints scalars only) is exactly the kind of global fact this model exists to make checkable — the D2 keep-test's content.

### Composition rules

- **L1 — oracle parity (ADR-0020 §3).** Identical law to backend-llvm L1: `Done` ⟺ exit 0 ∧ stdout byte-equal; `Trapped(_)` ⟺ exit 101 (⊥-identified, stdout ignored, classes never cross). Integer `Add/Sub/Mul/Neg` wrap; `Div/Mod` zero-guard → trap kind 0; signed `MIN / -1` → defined results **Div `MIN`, Mod `0`** (parity with `wrapping_div`/`wrapping_rem` — a value guard, *not* a trap); `Index`/`Update` OOB → trap kind 1; floats IEEE at width; float ÷0 is IEEE ±inf/NaN, **no trap** (ADR-0013 S13 amendment); all text via `flow-rt` on the host. CUDA twist: C++ signed overflow and `INT_MIN / -1` are **UB**, where LLVM `add` without `nsw` is *defined* — so wrapping is emitted via unsigned casts (BC2), and the div guards precede the operation exactly as in llvm.
- **L2 — determinism.** Byte-identical `.cu` for the same sealed IR; names from deterministic per-dump ordinals (the llvm `f{i}o{j}` scheme); launch geometry constants fixed (256 threads/block).
- **L3 — capability totality on Core, one shared ceiling.** Every Core op emits — in **launch form** at fn top level, in **inline form** (per-thread sequential device code) inside kernel bodies (§1). The only `Unsupported` cell is the non-canonical multi-merge loop — the identical ceiling as interp M1, rewrite R6, and llvm BL6, gated by the same `flow_ir::loop_plan` predicate (`flow-backend-llvm/src/lib.rs:41–56` is the reference gate); lifted together or not at all.
- **L4 — erasure (unchanged from llvm).** The erased set is **`Unit` | `IoToken` | `Str`** — none has a runtime representation on either site (a `Str` survives only as a host-side print-operand global, never as a value — llvm's scheme). Effect order is the token chain's topo order, realized as host statement order; tokens never reach the device, so device code is effect-free by construction (E2).
- **L5 — residency discipline (CUDA-specific).** Scalars live on the host; arrays live in device buffers; every handle lives on the host. **Every H↔D crossing is enumerated in §2's inventory; no crossing is implicit.** This is the rule that deletes the classic dual-residency stale-copy bug class — the price (a D→H round-trip per host-consumed `Index`) is accepted correct-first and recorded.

## 1. Execution mapping — the host/device split

**The split.** Everything runs on the host except array-bulk computation. Host: all scalar ops, guards, loop driving, IO, fn calls, and every array *handle* manipulation. Device: the data-parallel work — `Map`/`Zip`/`Enumerate` (elementwise), `Update` (full copy), top-level `Index` (single element), `Fold` (sequential reduction). Two realization forms, chosen by **context** (a pure function of the call graph — L2-safe):

- **Launch form** (fn top level): the op becomes a `__global__` kernel + one launch.
- **Inline form** (inside a kernel body): the op becomes per-thread sequential device code over per-thread locals. Bodies can contain any pure Core op — e.g. an `Index` on a body-local literal — and inline form *is* the oracle's evaluation order, per thread. A loop inside a `map`/`fold` body lowers as a top-level loop of the synthesized body fn (lower emits each body with fresh loop state — `flow-lower/src/emit.rs:191,296`), so body fns may contain canonical loops; inline form emits them as per-thread sequential loops under the same `loop_plan` gate.

**One-thread-per-element, not grid-stride** (BC3): elementwise kernels use `unsigned long long i = (unsigned long long)blockIdx.x * blockDim.x + threadIdx.x; if (i < n) …` with 256 threads/block, grid = `ceil(n/256)` **computed in 64-bit**. Index arithmetic is 64-bit throughout: `n` is a `u64` (`Ty::Array { size: u64 }`), and 32-bit `blockIdx.x * blockDim.x` products overflow for grids past 2³¹ threads. (The rejected alternative — an emission-time guard `n ≤ 2³¹−1` — adds a capability ceiling for zero M3 benefit; 64-bit costs nothing at these sizes.) Justification: `n` is a compile-time constant (`n` is in `Ty::Array`), bodies are per-element pure fns with no cross-element interaction, and occupancy tuning is nvcc's business; grid-stride exists for unknown/unbounded `n` and is recorded perf headroom (§7). This choice is correctness-neutral and deterministic.

**The fold problem — f32 non-associativity, grappled with.** The oracle folds **left-sequentially** — verbatim (`flow-interp/src/eval.rs:218–231`): the operand is the `(Acc, Array)` pair with **`acc` in slot 0** (`let mut acc = component(&src, 0)`), the array in slot 1, then `for e in elems { acc = eval_fn(body, (acc, e)) }` — one element at a time, in-order traversal, each body input assembled as the `(acc, e)` pair. A GPU tree reduction regroups the operations; for f32/f64 that changes rounding, so the GPU result differs in the last bits from the oracle's — and R1 compares bytes. Options weighed:

- **(a) Int-only parallel fold, float folds fall back host/single-pass.** Wrapping int add/mul *are* associative — but the fold body is an *arbitrary* closed fn `(Acc × T) → Acc`, and associativity of an arbitrary body is undecidable. Option (a) is sound only behind an associativity-*recognition* pass (add/mul-shaped bodies); without one it is unsound even for ints.
- **(b) Pin a reduction order the oracle matches.** That changes the oracle — i.e. changes the language (the oracle is the final arbiter, ADR-0022 D1 rank 1). It is an ADR candidate for Sapir, not a backend choice.
- **(c) Sequential everywhere, correct-first.** A **single-thread kernel** when the input array is device-resident: one launch; the thread runs the exact oracle loop over device memory, accumulator in per-thread local storage; in-body traps set the trap flag; the final acc crosses D→H iff scalar-typed (array acc stays as the result buffer). Byte-exact by construction, uniform across int and float, no recognition pass, no language change.

**Recommendation: (c).** (a)'s recognition pass and (b)'s oracle re-pin are both recorded headroom (§7); (b) additionally needs its own ADR.

**Op table** (source = the operand aggregate per §5.1 convention; "top level" = launch form, "in body" = inline form):

| op | fn top level | inside a kernel body |
|---|---|---|

**The fn-level walk's driver-ownership skip.** The top-level `topo_order` walk skips driver-owned morphisms by **`loop_plan` decide∪advance membership ∪ SCC incidence** — the llvm rule carried verbatim (`flow-backend-llvm/src/func.rs:252–290`; the skip itself is :280–285): plan membership is the precise rule because an exit-only payload chain (a computed exit value, an exit-arm `Print`) leaves the SCC but still belongs to the decide cone, and skipping by SCC incidence alone would re-emit it after the loop — dead recompute for values, a **double** side effect for `Print` (the llvm `exit_only_payload_emitted_once` miscompile class, pinned at `golden_ll.rs:198`). The CUDA emitter consumes the same `flow_ir::loop_plan` (never re-derived) and applies the identical skip in its fn walk; the loop driver emits the decide/advance cones, and they emit nowhere else.

**Call qualifiers (BC8) — the three-case rule, as built (S15).** Token introduction happens only via signature synthesis (ADR-0013 law i), so a token-free fn is pure **transitively** through the call graph. Qualifiers by case: (i) **token-bearing ⇒ host-only**; (ii) **token-free ∧ reachable from any kernel body ∧ (launch-form ops ∨ array-typed return, transitively) ⇒ Twin** — a host definition (launch form) **plus** a `__device__` inline-form twin: the **split emission is the base case, as built** (the S14 text's "inline form on both sites" is not what was built — host-inline loops over device-resident arrays would need unenumerated crossings; §7's "split emission" headroom row is therefore built, not pending). An array-typed return forces the twin only when the array *lowers* (an erased `Array{Unit}` return gets a single void `__host__ __device__` definition); the out-param convention writes the per-thread result into the caller's local. Twin-ness propagates **callerward through Call edges** (as-built S15 — a body-reachable pure-scalar fn calling an array-returning Twin must itself Twin, or its two-site definition would call the Twin's host definition on the device pass: illegal CUDA, the HW-1 class); (iii) **token-free ∧ NOT body-reachable ∧ contains launch-form ops ⇒ host-only** — a `__device__` instantiation of such a fn would have to launch a kernel from device code, which needs CDP/rdc, out at M3 (the case the two-case draft missed: `__host__ __device__` on a launch-form fn is illegal CUDA). Only **pure-scalar token-free fns** — no launch-form ops anywhere in the body — get `__host__ __device__`. The `__device__` constraints stand: device code may not call `flow-rt` (purity guarantees it never needs to) and may not launch kernels (no CDP at M3).

## 2. Memory model — device buffers, transfers enumerated and counted

- **Allocation.** A device buffer is `cudaMalloc`'d at array construction (per execution of the construction site). **Array literals upload once**: the literal's data is emitted as host `static const` data plus one `cudaMemcpy` H→D at the construction point. This dodges the llvm literal-explosion wall (array-scale-plan W2: clang `-O2` is superlinear over 3N per-element instructions, >25 min at N = 262144) — a C array initializer is O(n) *text* with **zero** instruction-level optimizer work. Honest caveat, mirroring W2's option 2a: the win is the removal of the superlinear term; its size is expected large but must be measured, not assumed. The host-static+memcpy mechanism is **launch-form-only** — it cannot execute mid-kernel: a body-local array literal (inline form) is constructed **per-thread in local memory** by an in-thread initializer, mirroring inline form's per-thread sequential semantics, and never crosses H↔D (inventory item 8).
- **Persistence and freeing — allocation-based ownership.** Buffers persist across ops within a fn; handles are host variables (rebind = pointer assignment). The freeing rule keys on **allocation, not handle liveness**: each fn `cudaFree`s exactly the buffers *it* allocated — tracked in a per-fn **allocation registry** (every `cudaMalloc` this fn emitted, in order) — at fn exit. Fn **parameters are borrowed** (caller-allocated, never freed by the callee). **(As-built S15, two amendments.)** (i) A **returned array escapes** — realized as a **pointer-value guard at the fn epilogue**: each registered buffer is freed unless it equals *any* array-typed component of the return value (a bare-array return: the return local; a product return: each surviving array field, recursively). The S14 text's name-based `Output` removal survives as the fast path, but the guard is what closes the shapes names cannot see: lower's `Dest::Ret` lookahead wires array-producing ops straight to the Return object with *no* `Output` morphism; a Phi-selected handle; a returned struct's array field (all three were S15 review findings, pinned by tests). (ii) The caller-frees rule is **not mechanized**: registration happens only at construction sites, so a call-result array consumed locally is never freed by the receiving fn — a bounded leak reclaimed at process teardown, matching the `main`-return rule (an array returned from `main` is reclaimed by context teardown — recorded, not leak-policed). Handle aliasing (a back-edge swap, a second handle bound to the same pointer) changes nothing: the registry tracks allocations, not handles, and the escape guard compares pointer values. Invariants, stated as implemented: **no double-free** — every buffer has exactly one allocator, hence exactly one freeing fn, and the escape guard skips the freed set's escaped members by pointer equality; **no use-after-free** — a buffer is freed only at its allocator's fn exit, and a buffer escaping that frame does so only as (a component of) the return value, which the guard exempts by value.
- **Loop-carried arrays.** The merge is a host handle variable; the back edge is a pointer swap. Under naive `Update` each iteration allocates one fresh buffer and the old one lives until fn exit ⇒ O(k·n) device memory for k iterations. Fine for the M3 corpus against 24 GB (testgen arrays are tiny); the back-edge free — the cheapest case of the last-use deduction (array-scale-plan 3a) — is recorded headroom. **(As-built 2026-07-22: both mechanisms now land where the shipped `flow_ir::last_use_plan` proves them — the in-place `Update` kills the per-iteration malloc+copy for the provable carried shape, and the back-edge free releases the remaining producer buffers per iteration under the pointer-value init guard; the O(k·n) default stays only where the plan can't prove (borrowed/escape). See the As-built (2026-07-22 last-use) section.)**
- **Scalars cross as kernel arguments** — they ride the launch; no memcpy.
- **The transfer inventory (L5's theorem; static per-op counts).**

  | # | Crossing | Payload | Frequency |
  |---|---|---|---|
  | 1 | H→D literal upload | `n · sizeof(elem)` | per literal-construction execution (per iteration if inside a loop); **launch-form only** (item 8) |
  | 2 | H→D launch args | `sizeof(args)` riding each launch (not a memcpy) | per launch |
  | 3 | H→D trap-flag zeroing | 4 B (`cudaMemset`) | **once per process** |
  | 4 | D→H trap flag | 4 B | **after every launch** (§3) |
  | 5 | D→H `Index` result | `sizeof(elem)` | per top-level scalar-elem `Index` |
  | 6 | D→H `Fold` acc | `sizeof(acc)` | per top-level scalar-acc `Fold` |
  | 7 | D→H CUDA error status | `cudaError_t` (4 B enum) — every `cudaMalloc`/`cudaMemcpy` return + `cudaGetLastError()` after every launch | per API call + per launch (§3's infra-failure exit) |
  | 8 | — (no crossing) | body-local array literal: per-thread local-memory initializer, mirroring inline form | per body-literal execution, per thread |
  | — | whole-array D→H | — | **zero, by construction** (L5) |

- **Consequence.** Uniform residency deletes the stale-copy bug class at the price of item 5's latency (and a pointless D→H→arg round-trip when an `Index` result feeds only device consumers — "scalar forwarding on device" is the recorded headroom). Correct-first; counted, not hidden.

## 3. Trap design — the device flag and the check-after-each-launch rule

- **Mechanism.** One `cudaMalloc`'d `unsigned int` device flag — zeroed by `cudaMemset` at program start (H→D, once per process), passed to kernels as a launch argument, read back by plain `cudaMemcpy` (no `__device__` symbol: the malloc'd buffer is exactly the §2 mechanism). A trapping thread stores the kind **plus one** — 0 stays the quiescent value (the memset), div_zero ⇒ `1u`, index_oob ⇒ `2u` — and returns. **(As-built S15:** the S14 text's bare-kind store collided with the quiescent 0 — a div_zero trap read back as "no trap", turning the oracle's exit 101 into exit 0 with garbage output, an R1 class cross; a 0-store could even erase another thread's OOB store in the same launch. Found by the S15 implementation review, fixed pre-GPU.**)** After **every** launch the host memcpy's the flag D→H (the copy is also the sync point — a default-stream D→H `cudaMemcpy` is host-synchronizing) and, if nonzero, calls `flow_trap(kind - 1)` on the host → stderr `flow trap: …` + **exit 101** — the same runtime, the same observable as llvm (the decode restores the `flow-rt` encoding, 0 = div_zero / 1 = index_oob — `flow-rt/src/lib.rs:60–65`). **(As-built 2026-07-22, S20 guard wave:** "every launch" reads as *every launch that can trap* — #14's capability qualifier, refined once more: an `Index` site the sealed graph's `bounds_proof` clears (provably in `[0, n)`) can never fire its bounds guard, so its kernel emits no guard and carries no flag parameter, its launch passes no flag argument, and no readback follows — trap-freedom is exact there; everything unproven (unknown, wrapping, captured, or loop-carried indices) keeps the every-launch convention on this page verbatim.**)
- **What can fire in-kernel** (both forms, both elementwise and fold kernels): `Index` OOB (kind 1); `Update` OOB (kind 1); integer `Div`/`Mod` by zero (kind 0). **(As-built 2026-07-22, S20:** an `Index` whose index the `bounds_proof` analysis clears statically in-bounds emits **no guard at all** — the guard is dead text exactly, never a behavior change; `Update` and every unproven `Index` guard as written here.**) **Not traps**: `MIN / -1` (a defined-result value guard — Div `MIN`, Mod `0`; llvm L1); float ÷0 (IEEE ±inf/NaN, ADR-0013 S13 amendment). Host-side scalar traps call `flow_trap` directly, unchanged. The bounds guard itself pins llvm's width rule (`flow-backend-llvm/src/func.rs:589–619`): extend the index operand **per its `Ty`** to `int64_t` — zero-extend for unsigned (the S13 u8 class zero-extends, never negative), sign-extend for signed — then a **signed two-sided compare**, `idx < 0 || idx >= (int64_t)n`; never compare against `size_t` directly (the usual arithmetic conversions would re-unsigned a negative operand into a huge positive one).
- **Why the check is after EACH launch.** R1 ignores stdout on trapping runs, so the stake is not stray prints — it is **class parity**. (i) Once a kernel has trapped, the oracle has stopped; no semantics governs values computed afterwards. A deferred check lets host code run on garbage: a garbage-fed loop guard could diverge (hang ⇒ harness timeout ⇒ class cross), or the program could reach exit 0 (class cross). (ii) First-trap-wins: the oracle's trap is the first in evaluation order; checking at each launch makes the native trap the first in launch order, so no later host-side trap can preempt an earlier device one. The price — one sync per launch, serializing the device pipeline — is the correct-first price; batched/deferred checks are headroom gated on this argument. Scope note: class parity + first-trap-wins bind **any** deferred-trap design on any backend; what the two-site structure specifically forces is the **flag + readback** mechanism — the device cannot call `flow-rt`, so the trap must cross D→H before the host can observe it.
- **CUDA error checking — the infra-failure exit.** Every `cudaMalloc`/`cudaMemcpy` return is asserted, and `cudaGetLastError()` is called after **every** launch (the same host point as the trap-flag readback). On any CUDA error the process prints the error string to stderr and exits **102** — a distinct **harness-visible infra failure**: not 0 (a `Done` data point), not 101 (a trap data point). The harness treats 102 as harness failure — a broken box, toolchain, or emitter bug — **never an R1 data point**, so an infra fault can masquerade as neither parity nor a legitimate trap. These error returns are themselves D→H crossings (§2 item 7).
- **Multi-thread trap races, honestly.** Several threads may trap in one launch; the flag's final value is whichever store lands last, so the *kind* can be nondeterministic within one kernel (div_zero vs index_oob). Unobservable under R1 — exit is 101 either way and stderr is not compared. **(As-built S15:** this claim is true only under the kind+1 encoding — every store is nonzero, so no store can erase another class's trap; under the S14 bare-kind encoding a div_zero's 0-store could erase a concurrent OOB trap, making the claim false.**)** A deterministic first-trap-kind ordering (ticket + `atomicMin`) is unclaimed headroom.
- **Output parity.** Pre-trap host prints are already flushed per call (`flow-rt/src/lib.rs:24`); trap-vs-print order on the host is the token chain's topo order (L4), unchanged from llvm.

## 4. nvcc float determinism — `-fmad=false`

- **The hazard.** nvcc's default `-fmad=true` contracts mul+add into FMA — one rounding where the oracle does two (Rust/LLVM does not contract without fast-math flags). On general inputs that changes bytes and breaks the differential. **Compile recipe: `nvcc -std=c++17 -fmad=false -arch=sm_89 prog.cu libflow_rt.a -o prog`.** `--use_fast_math` is forbidden (it sets fmad=true, prec-div=false, denormal flush, approximate intrinsics — every clause is a parity break); the recipe relies on the defaults `-prec-div=true` / `-prec-sqrt=true` and states them so a future flag sweep can't drift them silently.
- **Host side, same discipline.** `-fmad` governs **device code only**. Host float parity relies on the ISO default: `-std=c++17` (ISO mode) on the x86-64 baseline, which lacks FMA in the baseline ISA — the host compiler has no contraction to exploit by default. Host `-march=native` / `-mfma` is **forbidden** in the recipe: either can enable host-side FMA contraction and reintroduce the exact byte-drift the flag exists to kill.
- **Assumptions, documented as assumptions.** (a) sm_89 add/sub/mul/div/sqrt are IEEE-754 correctly rounded, matching host x86 for the same ops — a documented property of the architecture, but the differential is the evidence, not the manual. (b) Float `Mod` maps to `fmodf`/`fmod` — the same parity question llvm recorded open for `frem` (backend-llvm DESIGN §8); pinned by a differential case, falling back to a `flow-rt` call if it diverges (llvm's resolution path transfers verbatim). (c) **Cross-GPU/driver float determinism is not claimed** — the M3 sweep runs on one box; Core has no transcendentals, so basic-op IEEE conformance should make this moot, but "should" is not "verified". (d) NaN bit patterns are unobservable at the text level — `flow-rt` renders `NaN` via the same `Display` as the oracle — so NaN-payload divergence cannot cross R1.

## 5. The ADR-0020 contract realized

- **Signature.** `pub fn emit(ir: &CategoryIr) -> Result<String, EmitError>`; the `String` is the `.cu` translation unit (ADR-0020 §1). `EmitError` is per-crate, structured, renderer-free (C3): `Unsupported { feature: String, loc: SourceLoc }` ⊕ `Internal(String)` — the llvm taxonomy (`flow-backend-llvm/src/lib.rs:27–33`).
- **The `Unsupported` cells — three, each justified.**
  1. **Non-canonical loops** (multi-merge SCC / `loop_plan` is `None`) → `Unsupported { "nested loops" }` — the whole toolchain's one shared ceiling (interp M1, rewrite R6, llvm BL6), same predicate, lifted together or not at all.
  2. **Arrays embedded in products in device value contexts** → `Unsupported { "arrays embedded in products on device" }` **(as-built S15** — the S14 "nothing else at M3" list missed it; found by the S15 implementation review**)**. A product whose residual contains an array lowers to a struct with a `T*` field; on the device that field can only hold a per-thread local-memory or buffer-interior pointer — dangling once the struct escapes into global memory. The cell fires on kernel element types (every launch-form bulk-op site's global loads/stores, incl. arrays OF such products), Twin/`HostDevice` return types, and device-side locals — MINUS the shapes that provably stay per-thread: the input parameter (the fold body's `(acc, e)` pair) and the transient operand aggregates of bulk ops/calls (gathered field-wise, never stored to global memory). Host-side products holding handles are NOT the cell. Corpus-audited: zero hits across the 640-emission M3 sweep. Full support = by-value device products (§7 headroom).
  3. **Per-thread local arrays over 16384 bytes** → `Unsupported { "per-thread local array over 16384 bytes (<n> bytes)" }` **(as-built S15** — this section promised a documented cell for the array-typed `Fold` acc; the first implementation improvised**)**. A twin's produced local or the fold kernel's array-acc copy whose nominal flat byte size exceeds `MAX_LOCAL_ARRAY_BYTES = 16384` is rejected, not emitted (16 KiB sits far above the corpus — sepia's `[Pixel; 16]` is 192 B — and far below the local-memory wall).
  - **Examined and rejected from the list, each with its reason:** loops inside kernel bodies (inline form, §1); nested arrays (flat aggregates with static stride); `Str` (host-only print operand, llvm's scheme); token-bearing fns (host-only by hereditary purity, BC8). If implementation meets a genuinely unemittable shape, the honest move is a new recorded cell here and in STATUS — never a silent miscompile.
- **Deterministic emission** (ADR-0020 §5): byte-identical `.cu` per sealed IR (ordinal-derived names, fixed launch constants), golden-snapshotted.
- **Semantics parity** (ADR-0020 §3) = L1 + §3 traps + §4 flags, discharged by the §6 duty on raw **and** rewritten IR (ADR-0020 §4).

## 6. Differential harness — the vast.ai recipe, end to end

**The decision: full-remote `cargo test`.** The alternative (local-emit + remote-compile-run) was weighed and rejected for M3: it forks the ADR-0020 §4 duty into two phases, must ship oracle expectations to the box, and still needs a Rust-aware remote for `flow-rt` (a rustc-only remote is possible — `flow-rt` is dependency-free outside `cfg(test)`, so `rustc --crate-type=staticlib lib.rs` works — recorded as the fallback if remote cargo proves impossible). Full-remote keeps the differential *definition* identical to llvm's (compile+run in-test, oracle in-process, expectations computed on the spot — `differential.rs:134–152`), with `nvcc` swapped for `clang`. Exit-101 over ssh: under full-remote, the 101 is asserted by the test process *on the box*; ssh carries only cargo's own exit status — no exit-code laundering to design. Local macOS runs (no nvcc) skip-with-reason per HANDOFF §5.5; the skip is recorded in STATUS, never faked.

**The recipe.**

1. **Box.** Use **one** of the two running 4090s — **45170851** (0% util at S13 close) — and leave 45170852 untouched; if 45170851 is gone by execution time, rent fresh (on-demand 4090, **≥ 25 GB disk**) and record the substitution. Destroy-vs-keep for both is **Sapir's call** (next-session.md's standing warning); this DESIGN authorizes neither. Cost/hr and total are recorded in the session log. **(Executed S15, via the fallback:** Sapir declared both pre-existing instances unrelated; the leg ran on a **fresh rental** — RTX 4090, `nvidia/cuda:12.4.1-devel-ubuntu22.04` (nvcc 12.4.131, gcc 11.4, 12 vCPUs, 60 GB disk). One first attempt aborted: a flaky host stuck 18 min in `loading` (the abort-and-record rule applied, box destroyed un-rezzed). The working box booted in <1 min; preflight → rsync → green in one pass; destroyed post-run per §6.9. Total cost ≈ **$0.25** (incl. the aborted box), ~35 min wall.**)**
2. **Provision.** Image class `nvidia/cuda:12.x-devel-ubuntu…` — the **-devel** tag carries `nvcc`, the runtime tags do not; sm_89 needs CUDA toolkit ≥ 11.8, so 12.x is the recommended pin. Verify `nvcc --version` (re-image or install the toolkit if absent — recorded, not improvised); install rustup + stable; build essentials. The first `cargo test` downloads the full dev-dep tree (proptest, insta, tempfile, …) — a one-time network cost on the box, expected and recorded.
3. **Transfer.** `vastai ssh-url <ID>` gives the `ssh://root@<host>:<port>` endpoint; then `rsync -az -e 'ssh -p <port>' --exclude target/ --exclude .git . root@<host>:/root/flow/` — the box needs no git state.
4. **Preflight, before any sweep.** `nvidia-smi` (driver up, GPU visible) plus a one-program smoke test — compile and run one example (e.g. `abs`), expect exit 0 and oracle-equal stdout. A failed preflight stops the run here; no sweep minutes are burned on a broken box.
5. **Build + test.** `cargo build -p flow-rt && cargo test -p flow-backend-cuda`. `nvcc` discovery order mirrors `clang()`'s `$CC`-first behavior (`differential.rs:52–63`): **`$NVCC` → `$CUDA_HOME/bin/nvcc` → `which nvcc`**; absent ⇒ skip-with-reason.
6. **Link line — default pinned, verified as-built.** §4's recipe links the Rust staticlib on **Linux**, a first for the project (the llvm harness's bare `clang prog.ll libflow_rt.a` line has only ever run on macOS). The default tail is **`-lpthread -ldl -lm` appended after the objects** — no `-lc++abi`; the staticlib is PIC; glibc ≥ 2.34 absorbs these into libc, but Ubuntu 20.04-class images still need them explicit. **Verified S15 on Ubuntu 22.04 (glibc 2.35, gcc 11.4): the pinned default linked and ran every job — 640 compile-and-runs, zero link failures, no deviation needed.**
7. **Rules preserved verbatim** (next-session.md): oracle runs **before** `rewrite()` (IR taken by value); **closed-mode** testgen only (open `i32 → i32` has no native observable, BL8); `Unit → i32` entries get the result-printing wrapper; Diverged programs skip; runs are time-boxed — the llvm **15 s run timeout** is inherited (`differential.rs:35`) and each `nvcc` compile gets a **120 s** timeout; timeout ⇒ failure naming the program; `Done` ⇒ exit 0 + byte-equal stdout; `Trapped` ⇒ exit 101, stdout ignored; **exit 102** ⇒ harness-visible infra failure (§3), never an R1 data point.
8. **Sweep contents.** The 10 examples (abs, calc, fanout, fir, pipeline, sepia, seq_demo, sum_to_n, vector_add, zip_demo — `vector.flow` is the aspirational exhibit, not Core) + the closed testgen sweep at the llvm row's recorded scale — reproducibility is by **mechanism**, not copied numbers: `TestRunner::deterministic()` (`differential.rs:367`) plus the synced pinned `Cargo.lock`; **320 draws (256 + 64), ≥ 256 closed non-diverged** required (`differential.rs:370,392`) + the pinned special cases ported from the llvm suite (two sequential loops in one fn; **`exit_only_payload_emitted_once`** (`golden_ll.rs:198`); the loop-driven matmul `Update`; trap cases incl. `Update` OOB; float-print parity cases) — each on **raw and rewritten** IR.
9. **Cleanup — destroy by default (Sapir's standing rule, 2026-07-18).** Sync test artifacts/logs back for the session record. **The instance the session used is destroyed at session end**: vast.ai machines are provisioned per task/session and killed when the job is done — nothing session-provisioned stays up, or bills, past the session. (Sapir's explicit exception is required to keep a box; then remove the run's leftovers: the rsynced tree, `target/`, `~/.cargo`, and rustup.) Post-cleanup, `vastai show instances` confirms nothing is left billing unrecorded. The cost total is **$/hr (CLI rate) × measured wall**, cross-checked against the console invoice.

**Wall-time budget and parallelism.** The harness inherits the llvm fan-out: compile+run jobs are fanned across `available_parallelism` threads (`differential.rs:407–409`), and `nvcc` runs ≈ 2–6 s per small translation unit. Estimated envelope: the full sweep (320 draws × raw + rewritten, plus the 10 examples) is ≈ 20–60+ min serial, ≈ **5–15 min fanned** on the 4090 box. If the sweep exceeds the envelope's top end, **abort and record** — wall-time is accounting (§7), and a blowout says the box or the recipe is wrong, not that the test should wait longer.

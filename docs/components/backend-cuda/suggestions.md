## Candidates

0. **REGION-BASED EMISSION (Sapir's S16 mapping directive — the top item).** "Not fusion — correct mapping": the emitter should partition each fn's execution graph into maximal device-resident regions and emit ONE kernel per region, not one per bulk-op morphism. Today every `Index`/`Update` is a launch + readback (~24 µs) because residency is applied per op; per region, index arithmetic and reads stay on-device and scalars cross D→H once at the region boundary (matmul `cell`: ~130× fewer launches at N=64; with independent-iteration proof the whole matmul is one region = one kernel ≈ naive-CUDA). Trap semantics survive (one check per region; ops run in oracle topo order inside, the fold kernel's per-step pattern generalized); R1 differential untouched — the functor's image changes shape, not meaning. Subsumes #4 (scalar forwarding) and "backend-level fusion" as special cases. A backend DESIGN v2 revision — semantics preserved, mapping changed.

1. **By-value device products** — lifts the `Unsupported` cell "arrays embedded in products on device" (DESIGN §5, S15). Device-side product values materialize arrays as fixed-size C arrays inside structs (deep values, the oracle's semantics) instead of `T*` pointer fields; the host side keeps handle fields. A dual representation per site, so this is a DESIGN-level change with its own review — the payoff is deleting a capability cell, not perf.
2. **Back-edge buffer freeing — DISCHARGED (2026-07-22 last-use wave), together with the BC5 in-place Update amendment.** Mechanism: the shipped `flow_ir::last_use_plan` query (plan-last-use §2, rules 1-6 — the single source of dead/escape/carried facts, never re-derived) drives two consumer rows. (a) **In-place `Update` (rule 4):** when `dead_after(src, position(update))` holds and the consumer half proves the buffer fn-owned (a `LoopMerge` root: every same-field current-state alias dead at the update + an owned, read-nowhere-else, non-borrowed init — flow-ir's `last_use_borrowed_init_is_never_dead` pin; any other root: a fresh literal/bulk target, never `Proj`/`Phi`/`Call`-resident), `func::update_site` allocates NO fresh buffer and passes THE SOURCE HANDLE as `out` (race-free element write; bounds guard unchanged); the `__device__` twin skips its per-thread copy the same way (`kernel::DevEmit::emit_update`). The matmul4-class owned-init carried shape (the micro_loop_update golden) loses its per-iteration malloc+copy entirely — 3/3 → 2/2 excl d_trap; matmul4/matmul64 deliberately stay full-copy (borrowed init `b`, read by `cell` every iteration — byte-identical emission). (b) **Back-edge freeing (#2 proper):** `func::emit_back_edge_frees` at the back edge frees each array component of the merge's outgoing handle whose next-instance producer is a registered allocation, when `dead_after(merge, position(LoopBack))` holds and the init component is fn-owned — each free under the pointer-value init guard `if (merge.fE != init.fE)` (iteration 1's handle is the init's buffer, skipped; the fn-exit escape guard stays as the second line of defense). Map-in-loop carried shapes keep their per-iteration buffers but no longer accumulate to fn exit; where the plan says borrowed/escape, nothing is emitted (the O(k·n) default stays — conservative). Structural pins in `golden_cu.rs` (in-place exhibit, escape/read-after-write vetoes, borrowed-init veto, the twin form, the map-in-loop free text + sequencing); 144 → 151 green. Arena interplay: an in-placed site's offset stays reserved-but-unused (recorded v1 simplification — zones not recomputed; capacity slightly over-reserved). (Original note: free the previous iteration's buffer at the loop back edge (the cheapest case of the last-use deduction, array-scale-plan 3a). Kills the O(k·n) loop-carried residency (DESIGN §2); needs the last-use proof so a possibly-borrowed init buffer is never freed (the pointer-value guard's escape analysis, extended).)
3. **Batched trap checks** — one flag readback per N launches instead of every launch (DESIGN §3). Gated on the class-parity + first-trap-wins argument: between checks, host code must not branch on values a trapped kernel would have written. The check-after-every-launch design is the correct-first baseline; this is the latency win.
4. **Scalar forwarding on device** — an `Index` result feeding only device consumers currently round-trips D→H→launch-arg (DESIGN §2's consequence bullet). Keep such scalars device-resident; deletes pointless crossings from the inventory.
5. **Grid-stride + tuned launch geometry** — the 256/block one-thread-per-element scheme is correctness-neutral and deliberately untuned (BC3); occupancy/grid-stride for very large n is perf work to measure after the array-scale walls move.
6. **Pinned/page-locked H↔D memory + zero-copy trap flag** — removes the per-launch sync latency of the readback (DESIGN §3); pairs naturally with #3.
7. **Persistent kernels / CDP** — device-side launches would let Twin fns contain launch-form ops (today the three-case BC8 rule routes them host-only; DESIGN §1). Unblocks the inline-form split for bulk-bearing bodies.
8. **An nvcc `-O3` differential row** — the llvm `-O2` row's analog (S14 landed that one: 1280 runs, 0 divergences). The recipe is pinned (`-fmad=false` must survive any opt level); one harness row away.
9. **SoA layout / shared-memory tiling** — the AoS flat aggregate is the correctness-first layout (DESIGN §5); sepia-class image pipelines are the motivating shape if perf work ever opens here.
10. **Parallel `Fold`** — blocked on the oracle, not the backend: f32 non-associativity + arbitrary-body associativity is undecidable (BC4). Paths: an associativity-recognition pass (sound for add/mul-shaped bodies) or the oracle re-pin ADR candidate — **Sapir's call, recorded in DESIGN §1/§10**; the backend may not decide it.

## Toolchain variants (from Sapir's PTX question, S16)

11. **NVRTC / PTX toolchain variant** — the nvcc-binary dependency is the only thing a PTX-class change would actually remove. **NVRTC** compiles CUDA C++ *source* at runtime: the emitted `.cu` text is unchanged, only the compiler invocation moves to a library call — enables JIT and a toolkit-free `flow run --gpu` (M5 CLI territory). A raw **LLVM-NVPTX** backend (the Triton/Numba path) would NOT reuse the host-side llvm emitter (host IR ≠ device IR: address spaces, no host calls, NVVM intrinsics) and adds driver-API launch glue — more parts, no perf (nvcc's device pipeline is Clang→NVPTX→ptxas underneath). Verdict S16: keep nvcc/C++; spike NVRTC only if JIT becomes a requirement. Full discussion: `docs/notes/bench-matmul.md` §"Toolchain note".

## Emitter-quality (text hygiene — cosmetic, zero-cost after `-O3`, from Sapir's read of `matmul_cap.cu` in S18)

17. **Kernel shape dedup — DISCHARGED (2026-07-21 wave).** Mechanism: `kernel::emit_kernel_set` keys each site on the emitted kernel text minus its name (op kind, parameter/element types, n/flat counts, body-fn device name all ride the text), emits each unique shape once under the first site's `k{f_ord}_{site_ord}` name, and maps every launch to the survivor via `KernelSet.names` (deterministic fn×site order; the dedup map is lookup-only). matmul: 6 → 4 kernels (→ 3 with #12); zip_demo 8 → 5. (Sapir, S18 — "is there real consolidation?" Original note: one `__global__` per op *site*, so two identical `Index` sites emit two identical kernels (`k0_2`/`k0_3`, `k1_0`/`k1_1`). Consolidate by structural shape: emit each unique (op, param types, n) kernel **once** and launch it per site (the site's args ride the launch). Real wins: kernel count for repeated ops, nvcc compile time, review readability. This is a true consolidation gap, not cosmetics.)
17b. **Dedup key: canonicalize callee twin names** (S21 review finding, `golden_iota_fill` hand-read): `k0_4`/`k0_6` differ ONLY by the called twin's name (`fn1(in[i])` vs `fn2(in[i])`) while `fn1` ≡ `fn2` textually — #17's text-minus-own-name key can't see through callee names, so identical-body twins block kernel dedup. Canonicalizing called twin names in the key (or deduping twins first, by the same text key) collapses both. Cosmetic module-size win; zero behavior change.
18. **Smart arena allocation (v1.0) — DISCHARGED (2026-07-21 wave, plan-smart-arenas).** Mechanism: `arena::arena_plan` (the deduced BL7-shape query) assigns every NON-loop-cone buffer construction site a 256 B-aligned offset in one FnScope zone per fn (capacity = Σ align256(abi bytes), compile-time); `FnEmit::alloc_buffer` swaps each zone member's `cudaMalloc` for the pointer init `o8 = (double*)(arena0 + OFF)`, `kernel::abi_sizeof` gives C-layout-exact sizes (nominal undercounts padded products) with per-struct `static_assert`s against nvcc's `sizeof`, and `emit_frees` replaces the per-buffer frees with one zone release vetoed by the pointer-range escape test `escaped0` (rule 3 — pointer VALUES, zone granularity). Over 4 GiB/zone ⇒ `EmitError::Unsupported` (rule 4, the F7 precedent). `d_trap` excluded. Counts (excl d_trap, plan §7 gates in `golden_cu.rs::arena_gates_plan_section_7`): one-kernel matmul 8 → **1/1**, vector_add 7 → **1/1**, fir 4 → **3/3** (§7 said ≤3/≤2 — its cell missed that BOTH of fir's readback cells are advance-cone sites; recorded in the plan's Status line), micro_loop_update **3/3 unchanged** (the cone Update stays per-buffer). matmul64_cap: 8 → 1 malloc / 1 free, zero cone sites, 4 launches + 3 checks unchanged. **v1.1 is its own row (below).** (Sapir, S18; elaborated S19 as the S19 P0. 18a. **Arena v1.1 — last-use coloring + loop-cone zones** (plan §6, recorded not built; **scope after the 2026-07-22 last-use wave**): the last-use query's other two consumers landed (#2 + in-place Update), which shrank this row's remaining work: the cone **Update** site no longer allocates at all where rule 4 proves the carried source dead (its zone offset stays reserved-but-unused — the recorded v1 simplification), and the map-class carried buffers now free at the back edge (residency solved, malloc traffic not). 19. **Kernel-time instrumentation — step (a) DISCHARGED (2026-07-21 wave); step (b) RESOLVED (2026-07-25, S29) — and cuda's answer is a `✋` cell, not a seam.** (a) harness-level: `emit_with_opts(ir, &EmitOpts { perf_timing: true })` wraps every launch in CUDA events (one fn-scope event pair per site, created once; Record(start) → launch → Record(stop)+Synchronize+ElapsedTime, the stop recorded BEFORE `trap_check_after_launch` so the §3 convention is untouched) and prints machine-readable `FLOW_PERF launch=<kernel> ms=<%.4f>` per execution plus `FLOW_PERF total ms=<%.4f>` per fn at fn end. Default off: `emit` ≡ `emit_with_opts(default)`, byte-identical (goldens/differential ride the default). `cargo run -p flow-backend-cuda --example emit -- <file> --perf` emits the instrumented text. The llvm backend is deliberately NOT instrumented (harness-level timing suffices there — recorded). (b) **the language-level `time` builtin landed in S29** (spec `docs/components/lower/plans/plan-time-builtin.md`): `() -> time`, `flow_ir::Operation::TimeMs : IoToken → (IoToken, f64)`, an effect on the token chain exactly as this row predicted, realized via `flow_rt::flow_time_ms()` — which is a **host** clock. The llvm backend calls it (the pair's residual is a bare `double`); **cuda records `EmitError::Unsupported { "the `time` builtin (no CUDA clock seam)" }`** (`func::FnEmit::emit_morphism`; DESIGN §5 cell 5 + the L3 rider). 13. **Constant-divisor guard elision — DISCHARGED (2026-07-21 wave).** Mechanism: `kernel::const_int_operand` (the divisor's `Pair`-edge source is a Constant object) — a literal non-zero divisor elides the zero guard, a literal ≠ −1 elides the MIN/−1 value guard; applied in `FnEmit::emit_arith` and `DevEmit::emit_arith` (host, HostDevice `#ifdef`-split, and twin paths). 14. **Trap-param trimming on trap-free kernels — DISCHARGED (2026-07-21 wave).** Mechanism: `kernel::TrapCaps` — a syntactic device-trap-capability pre-pass (capable = integer Div/Mod, Index, or Update reachable through Call + map/fold-body edges, callerward fixpoint; float Div/Mod never counts).

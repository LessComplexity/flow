## What works

**M3 REACHED (S15).** The full ADR-0020 contract: `emit(&CategoryIr) -> Result<String, EmitError>` emitting a complete CUDA C++ translation unit — host/device execution mapping (scalars + IO + loop-driving host; array-bulk ops as `__global__` kernels, one-thread-per-element, 256/block, 64-bit indexing), allocation-based buffer ownership with the epilogue pointer-value escape guard, the cudaMalloc'd trap flag (**kind+1** encoding) with a host check after EVERY launch, the exit-102 infra protocol, `-fmad=false` discipline, sequential single-thread `Fold` (oracle order verbatim), `Update` full-copy kernel, BC8 three-case fn qualifiers (Twin-ness propagated callerward through calls), host-driven guard-first loop quartet + per-thread inline-form quartets.

**Emitter-quality wave (2026-07-21, suggestions #17/#12/#13/#14 — text-shape only, zero behavior change):** (a) **kernel shape dedup** (`kernel::emit_kernel_set`) — each structurally unique kernel emitted once, launched per site (matmul 6 → 4 kernels, zip_demo 8 → 5); (b) **dead host-side twins deleted** (`kernel::host_reachable`/`dead_host_twin`) — a Twin fn with no host caller emits no host definition and no launch-form kernels (matmul's `fn1`/`fn2` + `k2_0` gone: 3 kernels total); (c) **constant-divisor guard elision** (`kernel::const_int_operand`) — literal non-zero divisors drop the zero guard and the MIN/−1 branch on all three arith paths; (d) **trap-param trimming** (`kernel::TrapCaps`) — trap-free fns/kernels drop the trap parameter, call-site argument, post-call check, and the post-launch readback (sepia 2 launches/0 checks, vector_add 5/2, matmul 4/3; launch counts unchanged everywhere).

**Optimization-marathon W2 (2026-07-21, suggestions #18 + #19a):** (a) **smart arenas v1.0** (`arena::arena_plan`, plan-smart-arenas shipped) — one FnScope zone per fn covers every non-loop-cone buffer construction site: one arena `cudaMalloc` at fn entry, compile-time 256 B-aligned `arena0 + OFF` pointer inits (`kernel::abi_sizeof` C-layout-exact sizes, per-struct `static_assert` drift guards), one zone release at fn exit vetoed by the pointer-range escape test (`escaped0` — pointer values, zone granularity); loop-cone sites keep per-buffer `cudaMalloc` (v1.1 debt, recorded); over 4 GiB/zone ⇒ `EmitError::Unsupported` (rule 4). matmul capture form: **8 → 1 cudaMalloc / 8 → 1 cudaFree** (launch/trap-check counts unchanged); (b) **kernel-time instrumentation** (`EmitOpts::perf_timing` + `emit_with_opts`) — every launch wrapped in CUDA events (stop recorded before the trap check), machine-readable `FLOW_PERF launch=<kernel> ms=` per execution + `FLOW_PERF total ms=` per fn; default off ≡ byte-identical `emit`; `--perf` flag on the `emit` example. The llvm backend is not instrumented (harness timing suffices — recorded).

**Last-use wave (2026-07-22, suggestions #2 + the BC5 amendment — representation-only, consuming `flow_ir::last_use_plan` per plan-last-use §2, never re-derived):** (a) **in-place `Update` (rule 4)** — where the plan proves the source array dead at the update and the consumer half proves the buffer fn-owned (merge-rooted: same-field current-state aliases dead + owned non-borrowed init; otherwise a fresh literal/bulk target, never `Proj`/`Phi`/`Call`-resident), `func::update_site` allocates no fresh buffer and passes the source handle as `out` (same kernel, race-free disjoint-index write, bounds guard unchanged); the `__device__` twin skips its per-thread copy identically (`kernel::DevEmit::emit_update` — store into the source array, target slot aliases it). The owned-init carried class (the micro_loop_update golden) loses the per-iteration malloc+copy entirely (no `cudaMalloc` in the loop body; counts 3/3 → 2/2 excl d_trap); matmul4/matmul64 deliberately stay full-copy (borrowed init `b` read by `cell` per iteration — emission byte-identical to the checked-in artifacts, oracle -275/3748 re-confirmed). (b) **back-edge freeing (#2)** — `func::emit_back_edge_frees` frees the merge's outgoing array components at the back edge where `dead_after(merge, LoopBack)` holds, the next-instance producer is a registered allocation, and the init component is fn-owned — each free under the pointer-value init guard `if (merge.fE != init.fE)` (iteration 1 skipped; the fn-exit escape epilogue unchanged as second line of defense). Map-in-loop carried shapes no longer accumulate buffers to fn exit; borrowed/escape shapes keep the O(k·n) default. New structural pins: the in-place exhibit, the escape + read-after-write + borrowed-init vetoes, the twin form, the map-in-loop free text/sequencing/determinism.

**S20 guard wave (2026-07-22 — the kernel-gap fix's guard half; representation-only, consuming `flow_ir::bounds_proof` per its BL7 contract, never re-derived):** (a) **proven-`Index` guard elision** — where the proof puts an `Index` statically in `[0, n)`, the §3 bounds guard is dead text (trap-freedom is exact): `kernel::DevEmit::emit_index` emits the width-rule extension temp + the plain per-thread read (the fn's proof cached on `DevEmit.proof`), and `kernel::index_kernel` drops the guard for a trap-free site; everything unproven (unknown/wrapping/captured/loop-carried) keeps the guard byte-identical. (b) **`TrapCaps` proof refinement** — #14's "any `Index` ⇒ capable" becomes "any UNPROVEN `Index` ⇒ capable" (`Update` stays conservative), answered per site from the owner fn's cached proof (`TrapCaps.proofs`); the existing #14 machinery compounds it — a kernel whose only trap source was a proven `Index` drops the trap parameter, the launch's `d_trap`, and the post-launch readback (fewer host syncs). What fires on the corpus today: the constant readbacks (`c[0]`/`c[n²−1]` — matmul both forms, vector_add, zip_demo, micro_loop_update) go trap-free end-to-end; #17's shape key splits proven/unproven `Index` kernels of the same (elem, n) shape (matmul64: 2 → 3 kernel definitions; launch counts unchanged everywhere). **Scope honesty:** the one-kernel matmul's MAP kernel does not trim — its fold body's reads index by captured values (ranges don't flow through ADR-0027 captures ⇒ unproven) and its own integer `t / 64` / `t % 64` hold the body capable under #14's conservative rule; capture-range flow in the analysis (suggestions 14c) would light that path with zero further backend change.

**The M3 line is green on an RTX 4090 (vast.ai, fresh rental, destroyed after use per the standing rule):** the 10 examples + 320 closed testgen programs (256+64, ≥256 non-diverged), **raw and rewritten IR — 640 nvcc compile-and-runs, zero divergences**; exit-101 trap cases (incl. `Update` OOB, div-zero); float-print parity (incl. `fmod` — the DESIGN §10 question answered green); loop-driven matmul `Update`; two sequential loops in one fn; `exit_only_payload_emitted_once`; zero exit-102 infra failures. Golden `.cu` snapshots (13) hand-read; emit-twice byte-equal; the `Unsupported` pins on hand-built graphs.

**S21 ADR-0029 stage 2 (2026-07-22, plan-iota-fill-stage2 — the 5th `Unsupported` cell discharged):** (a) **`Iota`/`Fill` kernel realization** — host sites join the bulk-site family (`func::iota_site`/`fill_site`): arena-member output via the ordinary `alloc_buffer` path, BC3 geometry, 64-bit indexing, **no trap plumbing** (both ops total, `TrapCaps` false); the count rides as a `long long n` LAUNCH ARGUMENT rather than a baked literal — deliberately stronger than the plan's shape: `iota(4)` and `iota(5)` dedup to ONE kernel under #17's text key (`kernel::iota_kernel`/`fill_kernel`; the elem ctype is derived from the target type, not hardcoded — the ADR's `[i64; n]` annotation form cannot silently truncate if it lands). Device twins are local for-loops (`DevEmit::emit_iota`/`emit_fill`, siblings of `emit_enumerate`). Fill's erased-element degenerate keeps the graceful-degradation convention (param and store dropped). (b) **`Widen` scalar arms** (ADR-0029 amendment) — host and twin both emit the C cast `(target_ct)(val)`; scalar op, no kernel site, no arena membership, `TrapCaps` trap-free (pins: no `__global__`, no `arena0`, exact cast counts).

## What does not / known issues

- **Recorded `Unsupported` cells (4):** non-canonical (multi-merge) loops — the one shared toolchain ceiling via `flow_ir::loop_plan`; **arrays embedded in products in device value contexts** (S15 — a pointer-field struct cannot live in global memory under the handle model; transient operand aggregates and the input parameter excluded as provably per-thread; corpus-audited: zero hits in 640 emissions); **per-thread local arrays over 16384 bytes** (`MAX_LOCAL_ARRAY_BYTES`, the DESIGN §5 documented cell); **a fn arena over 4 GiB** (`arena::ARENA_MAX_BYTES`, plan-smart-arenas rule 4 — same F7 precedent). Full support for the second cell = by-value device products (suggestions). (`iota`/`fill` discharged S21 — stage 2 above.)
- **nvcc absent locally** ⇒ the differential legs skip-with-reason locally (HANDOFF §5.5, never faked); the M3 evidence is the remote run (see the session log).
- **Recorded-not-fixed (honest notes, DESIGN §2):** a call-result array consumed locally is never freed by the caller (bounded leak, reclaimed at process teardown); per-iteration loop buffers where the last-use plan can't prove (borrowed/escape shapes — e.g. matmul64's borrowed init) still reclaim at teardown (the O(k·n) note — the provable classes now in-place or back-edge-freed, 2026-07-22); an array-typed *open* entry input emits `flow_main(nullptr)` (emission-totality only — the closed-mode harness never runs open entries; llvm's zeroinitializer rule).
- **Upstream note:** an array-typed loop-exit binding inside a map/fold body is rejected by flow-lower (L1201) — the emitter's twin path is ready for it, but the shape is unreachable from the surface today.

## Invariants enforced (and where in code)

- L1 oracle parity — `tests/differential.rs` (the M3 evidence above); R1 class discipline (exit 0/101/102).
- L2 deterministic emission — ordinal/counter naming only; emit-twice pins on all 10 examples (`tests/golden_cu.rs`, `src/kernel.rs`); the arena assignment walk is topo-ordered with lookup-only maps, instrumented emit pinned byte-deterministic too.
- L3 one shared ceiling — `flow_ir::loop_plan` consumed, never re-derived (`src/lib.rs`, the gate ≡ llvm's).
- L4 erasure (`Unit | IoToken | Str`) — `src/ty.rs:lower_ty` → `None`; residual rule everywhere.
- L5 residency — zero whole-array D→H by construction (review-verified); the §2 transfer inventory realized exactly (`src/func.rs`, `src/module.rs`).
- Ownership: no double-free / no use-after-free — per-fn allocation registry + epilogue frees value-guarded against every array-typed component of the return value (`src/func.rs:emit_frees` + `escape_lvalues`; pins incl. product/nested/Phi returns). **W2 (arena v1.0):** zone members are not individually registered; the zone release is vetoed iff an escape lvalue's address lies in `[arena0, arena0 + capacity)` — the same pointer-VALUE comparison class at zone granularity (`escaped0` range tests; cone-site buffers keep the per-buffer value-guarded frees).
- Trap semantics — flag stores kind+1, host decodes (`src/module.rs` PRELUDE); guards after every launch **that can trap** (`src/func.rs:launch_and_check` — #14's `TrapCaps` trim removes only the provably-dead readbacks; **S20: a `bounds_proof`-proven `Index` is trap-free exactly — its kernel/twin emits no bounds guard and its launch skips the flag argument + readback**; capable sites keep the every-launch convention, class parity + first-trap-wins intact; #19a's event stop is recorded BEFORE the check, instrumentation or not); width rule `idx < 0 || idx >= (int64_t)n`, never `size_t` (`src/kernel.rs:bounds_cond`).

## Performance notes (numbers + bench name + date; regressions flagged)

**First measured numbers (S16, `docs/notes/bench-matmul.md`, vast.ai RTX 4090):** the v1 execution strategy costs **~24 µs per launch-form op** (launch + trap-check sync + per-`Index` readback) — flow-cuda loop-form matmul N=64 12.16 s / N=128 99.8 s, i.e. Θ(N³) launches; the same algorithm as one kernel is 3.8M× faster at N=64, and the same `.flow` source on flow-llvm is 38× faster (on a laptop CPU). The walls are named: expressibility (L1108 — no captured map bodies, so no one-kernel GEMM in Core) and the per-op launch/sync floor (DESIGN §3's correct-first price). M3's claim stands: correctness only.

**S18 — ADR-0027 landed, the wall is gone (same note, S18 section):** the capture form (map over cells + inner fold over captured arrays, ONE `__global__`) runs N=64 in **277 ms** (44×), N=128 in **278 ms** (359×), N=256 in **278 ms** — flat: 4 launches total, the rest is process startup (CUDA context init). At process scale it beats the naive-C binary (311–333 ms) and the cuBLAS binary (469–496 ms) on the same box. Kernel-time instrumentation is the next perf-harness row. Emitter-quality gaps (nvcc warnings on the bench run) recorded in suggestions #12–18 (kernel shape dedup, arena allocation, guard elision, trap-param trimming, copy propagation).

**Emitter-quality wave (2026-07-21) — module-shape deltas on the one-kernel matmul (local text measurement; no re-bench yet):** 6 `__global__` → **3** (dedup + dead-twin deletion), host-side `static` fn definitions 3 → **1** (`flow_main` only), trap-check readbacks per execution 4 → **3** (the trap-free enumerate drops its sync; launch count unchanged at 4). The remote perf effect (the readback is the per-launch sync of the S16 note) is to be measured on the 4090 with the bench harness.

**Optimization-marathon W2 (2026-07-21) — structural deltas (local text measurement on `benches/matmul`; box wall-clock rows land with the marathon sweep):** matmul64_cap (capture form): `cudaMalloc` 8 → **1**, `cudaFree` 8 → **1** (one 197376 B fn zone, 8 members, zero cone sites; launches 4 / trap-checks 3 / kernels 3 unchanged); matmul64 (loop form): 7 → **4/4** (main's 33280 B zone + 3 cone sites staying per-buffer — the recorded v1.1 debt); one-kernel matmul: 8 → 1/1, vector_add 7 → 1/1, fir 4 → 3/3, loop_update unchanged at 3/3 (all excl d_trap; plan §7 gates). #19a's `FLOW_PERF` lines give the sub-startup kernel-time rows the S18 note needed (process-wall floor ~277 ms hides kernel time); the perf-timing text adds one host sync per launch only where #14 had already skipped the readback.

**Last-use wave (2026-07-22) — structural deltas (local text measurement; box wall + residency rows are a later wave — the emitted `.cu` cannot run locally without nvcc):** micro_loop_update (the O(k·n) exhibit): **3/3 → 2/2** excl d_trap — the cone Update site allocates nothing where rule 4 proves the carried source dead (the launch is unchanged, `out` = the source handle); the loop body has zero `cudaMalloc`. matmul64 (loop form): **byte-identical** — its borrowed init `b` (read by `cell` every iteration) vetoes both mechanisms, deliberately (in-place would corrupt the dot products; the plan's composition is the conservative default). Map-in-loop shapes keep their per-iteration malloc but gain a back-edge free per iteration — residency O(k·n) → O(n), API-call count unchanged. matmul4 oracle re-confirmed via `flow_interp::run`: prints `-275`/`3748`.

**S20 guard wave (2026-07-22) — structural deltas (local text measurement on `benches/matmul`, before/after diffed mechanically; box wall-clock rows land with the marathon sweep — nvcc is absent locally):** matmul64_cap (one-kernel form): trap-check readbacks per execution 3 → **1** (the two constant readbacks `c[0]`/`c[4095]` prove; the map launch keeps its check — the fold body's captured-index reads don't prove, and the map body's `t / 64` / `t % 64` hold it capable regardless), `d_trap` launch args 3 → 1, guard texts 3 → 2 (the readback kernel's guard gone — it is now the plain `*result = arr[(unsigned long long)idx];`; the fold body twin's two in-twin guards stay byte-identical), launches 4 unchanged, kernels 3 unchanged; matmul64 (loop form): checks 5 → **3** (cell's two in-loop reads and the `Update` keep theirs — loop-carried/conservative), `d_trap` args 5 → 3, kernels 2 → **3** (the proven readbacks split off the deduped capable Index kernel — the #17 shape key carries the guard/param text), launches 5 unchanged. Each dropped readback was a host sync (the §3 flag memcpy is the sync point) — the wave's measurable effect is fewer syncs per execution; nvcc compile/run is the box leg (later wave).

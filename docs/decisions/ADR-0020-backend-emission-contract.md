# ADR-0020: Backend emission contract — one convention, one runtime, oracle-parity semantics

Date: 2026-07-17 · Status: accepted — autonomous (Session 12, under Sapir's S12 "complete all" pre-authorization), **flagged for Sapir's review** (next-session.md), revisable

## Context (what forced the decision; spec refs)

P5 begins the backends. `categorical-model.md` §7.5 reserved exactly this ADR: `F_LLVM`/`F_CUDA`/`F_Verilog` are parallel realizations of one contract `CategoryIr → TargetText` (the strategy shape, FRAMEWORK §4.4/§7.4), and the shared contract must be fixed **before** the first backend is written. Constraints already law: backends emit source text piped to external toolchains (HANDOFF §5.5); toolchain absence ⇒ skip-with-reason (§5.5); the interpreter is the oracle and every backend is judged by differential tests against it (§5.4, §7.3); the oracle's semantics are pinned in interp/DESIGN (wrapping integer arithmetic, `Trapped(DivZero|IndexOob)`, float rendering = Rust shortest round-trip `Display`, output = the token log); rewrite/DESIGN R1 defines the equality relation (`Done` byte-exact, traps ⊥-identified, classes never cross). Three open questions forced here: (a) where the shared contract lives, (b) how a compiled artifact reproduces oracle traps (LLVM integer division by zero is UB — a raw functor image is *not* oracle-equal), (c) how compiled output reproduces the oracle's float text (`4080`, `5.375`) — C `printf` formatting differs from Rust `Display` on general values, which would fail every differential test on random programs.

## Decision (imperative)

1. **Contract by convention, no shared trait/crate yet.** Every backend crate exposes `pub fn emit(ir: &flow_ir::CategoryIr) -> Result<String, EmitError>` — the `String` **is** the `TargetText` (one translation unit: `.ll` / `.cu` / `.v`). `EmitError` is per-crate, structured, renderer-free (C3), with at least `Unsupported { feature, loc }` (capability-matrix rejection — the ✋ cell, naming the matrix row) and `Internal`. The CLI later binds the three `emit`s into a registry (selecting a 2-cell); a shared trait is extracted only when that third consumer exists (FRAMEWORK §5 YAGNI).
2. **One shared runtime, `crates/flow-rt`** (new workspace member): a `staticlib`+`rlib` of `#[no_mangle] extern "C"` functions — `flow_print_{i32,i64,u8,bool,f32,f64}(v, newline)`, `flow_print_str(ptr, len, newline)`, `flow_trap(kind) -> !` (writes `flow trap: div_zero|index_oob` to stderr, exits **101**). Emitted code calls these instead of libc `printf`/UB division. Float text is thereby Rust `Display` — **oracle parity by construction**, for every backend (CUDA prints are host-side — E2 keeps effects out of kernels; the Verilator C++ harness links the same runtime). No hand-rolled formatter, no drift.
3. **Semantics parity is the functor's target definition**: integer `Add/Sub/Mul/Neg` compile to wrapping ops (LLVM `add` **without** `nsw` — spec §8.1's `nsw` is illustrative; the oracle wins, HANDOFF §5.4); integer `Div/Mod` compile to a zero-check branching to `flow_trap(DivZero)`; `Index` compiles bounds-checked to `flow_trap(IndexOob)`; floats are IEEE at width. A compiled program is oracle-equal per rewrite R1: `Done` ⟺ exit 0 + byte-equal stdout; `Trapped(_)` ⟺ exit 101 (⊥-identified; stdout ignored on trapping runs); divergence has no compiled fuel analog — differential inputs are terminating by construction (testgen) plus the examples.
4. **Differential duty per backend** (the P5/P6/P7 DoD instrument): all `examples/*.flow` + `flow-rewrite` testgen programs (both raw and post-`rewrite()` IR), compiled and executed where the toolchain exists; toolchain absent ⇒ `#[ignore]`-with-reason recorded in the component STATUS — never a faked pass.
5. **Emission is deterministic**: byte-identical output text for the same sealed IR (golden-snapshotted).

## Consequences

One extra tiny crate (`flow-rt`) added to the workspace and to the §6 layout; linking cost at `clang` invocation (staticlib path passed by the harness/CLI). Backends never own formatting or trap policy — deleted class of cross-backend drift. The `nsw`/UB deviation from spec §8.1's illustration needs no errata (the section is expository; §8.5's correctness statement is what binds, and it is defined against the oracle). Verilog's mapping of traps is constrained by this ADR only at the harness boundary (its FSM asserts a trap line; the C++ wrapper calls `flow_trap`) — detailed in backend-verilog DESIGN. If Sapir vetoes exit-code 101 or the runtime shape, only the harness and `flow-rt` change; emitted-op semantics stand with ADR-0013/interp.

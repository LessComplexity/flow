# Matmul — S27 (2026-07-24): FMA product face + rung 3 packing + panel residence + loop→map lifting — LOCAL

Square GEMM `c[i][j] = Σₖ a[i,k]·b[k,j]`. Times in **ms**, min of runs shown.
**One machine, LOCAL: Apple M4 Pro** (arm64 NEON, 14 threads, 48 GB, Homebrew
clang 22.1.8; spec row stamped atop the CSV). The vast.ai box leg is still owed
(balance 0 at close — S28 opener); this file is the same-machine local matrix
Sapir asked for. Raw: `benches/matmul/results-s27-local.csv` (one-machine rule).
Flow rows = process wall min-of-3 (compute tables = `FLOW_PERF` llvm timer);
cpp/rust self-time; **no chapel locally** (chpl not installed — box-only leg).

**What changed since S26:** (1) **FMA contraction, product face** — the tiled
kernel emits per-instruction `contract` flags (`EmitOpts::contract`; the driver
flag never retrofits textual IR since LLVM 14 — golden-verified); `-fma` legs are
the product face, **numerically-equal-not-byte-equal** to the conformance legs by
design (single rounding; rel-tol + disasm gated). Conformance legs stay bit-exact
to the interp oracle. (2) **Rung 3 packing + panel residence** — b is read through
a packed j-tile-major 64-aligned panel; the nest is j-tile-outer so the panel
stays resident in private L2 across each thread's row blocks (b-traffic
÷i_blocks/thread). On this machine the residence gain is ~nil (M-series SLC
already held b) — the zen2 box is its test. (3) **Per-width TJ** (f64→8), k-unroll
×2, prefetch. (4) **loop→map/fold lifting (S27b)** — the `flow-llvm` LOOP-form
legs below now lift to map{fold} and tile: same emission class as the cap legs.

## Caveats before the tables (honesty rows)

- **numpy here is Apple Accelerate (AMX/SME matrix coprocessor)**, not OpenBLAS
  on NEON: 3.2 TFLOP/s @1024 f32 — different silicon than the NEON pipes every
  other leg uses. It is the platform BLAS and belongs in the table, but the gap
  is coprocessor-vs-SIMD, not kernel-vs-kernel. `OPENBLAS_NUM_THREADS=1` does
  NOT pin Accelerate — the numpy-1t rows are identical to numpy and are dropped
  as unmeasurable locally. numpy runs **fp32** (the standing S26b pairing flag).
- **Flow 2048/4096 rows are absent locally**: 3 arrays + packed panel exceed
  macOS's 64 MB hard stack ceiling (`ulimit -s hard`). Baselines (heap arrays)
  carry 2048. llvm heap lowering is the recorded enabler; the box (Linux,
  `ulimit -s unlimited`) owes the 2048/4096 flow rows (S26c directive).
- cpp/rust mt = row-partitioned `std::thread`/scoped threads, T=14
  (`hardware_concurrency`; no cgroup locally).
- Every leg's two printed outputs agree byte-for-byte at every shared N across
  all languages (`out=` columns in the CSV) — incl. the lifted loop-form legs.

## Measurement basis (S27c fairness fix — Sapir's catch)

The baselines **self-time compute only** (per-iteration ms inside a warm
process; their startup is excluded). Timing flow by **process wall** therefore
charged flow its spawn + pool init + print against baselines that pay nothing —
unfair, and it inverted the small-N story. The verdict tables below are
**compute vs compute**: flow = `FLOW_PERF` kernel timer, baselines = their
self-timed iteration. Residual asymmetry, noted: baselines iterate warm-cache in
one process while flow's timer wraps one cold-ish pass — this still slightly
*understates* flow. Wall table above stays for the e2e picture (that gap is the
process floor, ~5–9 ms — the CLI/daemon story, not the kernel's).

## The lift, measured (S27b)

`flow-llvm` loop-form legs (`examples`-style `mut`/`Update`/cross-fn-`Call`
matmul — `matmul4..128.flow`) now emit the same packed tiled kernels as the cap
forms (byte-level tile markers verified; outputs byte-equal to every other leg).
Wall at N≤128 is pure process floor (7.2–8.9 ms flat) — the kernel is invisible
at these sizes; the box 256+ loop-form legs will carry the numbers. The
structural fact is the point: **the naive loop program and the map/fold program
are now the same emission** (S26's non-tiling pin inverted).

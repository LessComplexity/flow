# Matmul — S26 (2026-07-23): BLAS rung 2 — TI register blocking + the fixed-TJ split

Square GEMM `c[i][j] = Σₖ a[i,k]·b[k,j]`. Times in **ms**, min of runs shown. Two
boxes this session, same machine class: **box** (vast.ai EPYC 7B12, zen2, AVX2 —
the standing matrix; section below) and the **s26b box** (same offer/CPU — the
framing-fix sweep; its own section in the verdict tables). The tile-vs-no-tile
self A/B is **local-only this wave** — runner.py carries no `--no-tile` legs, so
the box table reports the rung-2 flow legs vs the standing baselines plus the
S25-box rows where comparable (the A/B evidence is the emitter session's local
`tile_ab.sh` runs). Flow rows = `FLOW_PERF` llvm timer, min-of-3; chapel/numpy/
cpp/rust self-time as always. **S26b framing (Sapir): every ratio verdict is
1t-on-1t or par-on-par** — C++/rust threaded baselines (`cpp_mt`/`rust_mt`,
quota-aware) stand next to the naive ones; mt-flow vs 1t-baseline rows are gone.

**What changed since S25:** (1) rung 2 in `emit_tiled_map` (backend-llvm `func.rs`):
`TILE_I=4` register blocking — one `b[k, j0+lane]` vector load feeds TI rows'
accumulator chains (b-traffic ÷TI), gated on `site.rows > 1 && site.b.ci == 0`, the
record's row-invariance fact cashed; per-cell op/operand/k-order preserved exactly
(the rung-1 bit-exactness theorem applied over rows). (2) The fixed-TJ main/remainder
split on both axes: compile-time-constant trip counts on the main body (the S25 box
disasm showed the runtime `tj` bound holding clang at xmm), runtime-bound remainder
for partial tiles/boundary rows. (3) Box toolchain: clang-18 via llvm.sh replaces apt
clang-15 (the recorded gotcha fix; clang version now a comment row atop the CSV).
(4) `--no-tile` byte-stable (A/B control preserved); 1-D sites unchanged.

Readings (box):

1. **Rung 2 lands where the signal is clean — single-thread:** f32@1024 84.9 ms
   wall vs S25's 568.3 same-shape row (6.7×; 4.1× even against S25's clang-18
   compute retime 352.6). TI=4 b-reuse + the fixed-TJ split is a ≥4× kernel-level
   win at f32, 2.4× at f64, toolchain held as constant as the two boxes allow.
2. **The fixed-TJ split unlocked full-width vectorization, as designed:** the f32
   512 kernel is 28 `ymm` `vmulps`/`vaddps` with **zero** xmm/scalar vector ops
   (f64: 52 `ymm` …`pd` ops) — S25's xmm/partial nest is gone. **But clang-18
   still emits no `vfmadd`** under `-ffp-contract=fast` (split mul/add — the same
   shape as S25's arm64 `fmul`+`fadd`): ~2× FLOP density left on the table, a
   named follow-up class (contraction is the compiler's call at this recipe).
3. **Parallel f32@1024 is pinned at ~15.9 ms on this box class** (S25: 15.7): the
   62-thread cell does not see the 4× kernel gain — the wall there is memory/
   startup, not compute (f64 par did move 33.9→23.3, 1.45×). Rung 3 (packing +
   k-panels) is exactly the rung that addresses this floor.
4. **The numpy gap, like-for-like f64: 13.8× → 7.4× @1024, 9.95× → 8.1× @512** —
   rung 2 cashed ~1.9× of its projected 2–4× at par; the larger 1t kernel gain
   (2.4–4×) is what rung 3 must convert into the parallel cell. (s26b box
   corroborates in-band: 6.2× @1024. And see the width note under the par
   table — the numpy legs are fp32; the like-for-like f32 gap is 3.9× par,
   3.3× 1t.)
5. **chapel loses every cell ≥256 now:** the N=256 startup cell that edged chapel
   in S25 flips to flow 1.4×; the framing-fixed s26b table puts chapel mc at
   3.1–9.6× behind flow everywhere (both widths, 256 through 1024).
6. **The `matmul128.ll` stall is not clang-15-specific:** clang-18 on znver2 also
   hung >15 min on the loop-form array-literal module (killed per protocol; the
   S13/S16 pathology record should drop its "clang-15-specific" framing). Cap
   forms unaffected — all tiled legs built in seconds.
7. **Protocol note:** the cuda:12.4.1-devel image has no pip, so the driver's
   `pip3 install numpy` line no-op'd; numpy 2.2.6 was installed box-side
   (`apt python3-pip` + pip) before the numpy leg ran — s26_box.sh should re-add
   the apt `python3-pip` line s25_box.sh had (s26b_box.sh carries the fix).
   chapel-gpu legs skip as always (binary not built by runner.sh).
8. **Threading the naive baselines changes the constant, not the verdict**
   (S26b): cpp-mt scales 53× over its 1t self on 62 threads (7,300→138.1 ms
   @1024 f32), rust-mt 58× on 61 (7,044→120.8) — near-linear — and flow's pool
   still beats them 10.9×/9.5×. The deleted 475× row's honest par-on-par form
   is **10.9×**: the advantage is the rung-2 kernel, not the thread count.
   chapel-1t lands in the same naive class (6,256 ms @1024) — chapel's
   competitiveness is parallelism, not kernel quality.
9. **numpy-1t is the pure kernel-gap cell:** OpenBLAS single-thread (22.7 ms
   @1024) beats flow 1t (75.3 ms wall) 3.3× at f32 — that is the BLAS ladder's
   remaining rungs with no threading on either side. flow's 62-thread pool
   (12.7 ms) already sits 1.8× ahead of OpenBLAS *single*-thread; the par
   table's 3.9–6.2× OpenBLAS lead is what rung 3 + `vfmadd` contraction must
   close.
